# Handoff router API history

Dated notes on API changes behind this skill. Newer entries can supersede older ones. `api-reference.md` holds the current shapes.

- 2026-07-15: DISTRO-4614 (edge #959, 2026-07-09) removed the 409 representability rejection on handoff-router-update — app-built (representable:false) routers are now edited via an opaque-preserve overlay (rows matched by ruleId; app-only fields and untouched rows preserved; no row removal/reordering in overlay mode). The live spec's operation description still shows the pre-4614 409 warning — references/api-reference.md is the truth. Handoff writes are Schedule-only (no Redirect/timeout; ConvertLead is the only CRM action — 400 otherwise)
- 2026-07-02 (DISTRO-4550, PR #897): NO activate/deactivate and NO status field — every write is live on success.
- 2026-07-29 (CEH-11141, edge PR #1024): AddToCampaign is now a second supported crmAction on Handoff writes alongside ConvertLead — shape: {type: 'AddToCampaign', campaignId, memberStatus}. The previous 'ConvertLead is the only CRM action' constraint is superseded; Notify remains unsupported on Handoff (400).
- 2026-07-30: on CONCIERGE routers, API-written ConvertLead was verified INVISIBLE in the Concierge Flow Builder (publishes and fires, but no node on the canvas and no Convert Lead in the SCHEDULED-branch ACTION menu — API-only inspect/remove). Whether the Handoff router UI renders API-written crmActions is NOT yet verified — until it is, treat them as potentially invisible to admins and call out any crmActions write explicitly in the plan and the result
- 2026-08-13 (CEH-11300/CEH-11302, edge PR #1069): Three Handoff write-model changes — (1) catchAll is now OPTIONAL on handoff-router-update: omitting it preserves the router's existing catch-all (still REQUIRED on create at that time). (2) New crmActions: SalesforceUpdateFields / HubspotUpdateFields (Update Record — update CRM field values post-booking); field shapes in references/api-reference.md. (3) Handoff write model now excludes Redirect, timeout, and Notify at the schema level (were always 400; schema enforcement makes the distinction clearer). campaign-list and campaign-search are now available to look up Salesforce campaignIds for AddToCampaign actions
- 2026-08-13 (CEH-11303, edge PR #1072): SalesforceUpdateOwnership / HubspotUpdateOwnership added as new crmActions for both Concierge and Handoff — {type: 'SalesforceUpdateOwnership', contact: [{object, field}], lead: [{field}]} and {type: 'HubspotUpdateOwnership', contact: [{object, field}]} — always assigns the CRM record owner to the booked host (index 0, single-assignment routes only). Round-trips only when every route's assignTo is index 0; otherwise representable stays false
- 2026-08-18 (CEH-11358, edge PR #1087): catchAll is now OPTIONAL on both create and update — omitting it produces a router with no fallback path (unmatched requests are not scheduled). The 'required on create' constraint is lifted.
- 2026-09-03 (CEH-11588/CEH-11589, edge PR #1151): Two changes. (1) SalesforceCreateEvent and HubspotCreateEngagement added as new Handoff crmActions (Create Event — post-booking calendar event in CRM). Settings: relatedTo REQUIRED (Handoff rejects ExplicitObject/RelationDisabled relations with 400; a missing relatedTo returns 422 at publish; CEH-12077, edge PR #1890, 2026-11-04), meetingCancellationBehavior (default DoNothing), guestsBehavior (default DoNothing), owner (default Assignee). Full field shapes in references/api-reference.md. (2) handoff-router-get and handoff-router-list now return the COMPLETE crmActions chain — previously unmodellable nodes collapsed the whole array to null; now they become an Other{kind} read-only placeholder and the walk continues down the chain so representable siblings are preserved. Other is read-only and REJECTED on write; representable becomes false when any placeholder was emitted
- 2026-09-04 (CEH-11599, edge PR #1154): the read-only ContactOptions outcome variant now exposes its three CRM-action chains — {type: 'ContactOptions', meeting?, callSuccess?, callMissed?}, each branch an ordered list of the same crmAction union incl. Other (null = branch absent, [] = present with no actions). Kept in the variant list for accuracy, but Handoff routers never actually produce ContactOptions (it is a Concierge call-flow node); it stays read-only/unwritable.
- 2026-10-23 (CEH-12303, edge PR #1953): New assignment type UseAssignmentTable added to Handoff router create/update. Shape: {type: 'UseAssignmentTable', ruleId: '<assignment-table-ruleId>', columnKey: '<column-key>'}. Constraints: (1) only valid on a route row, NOT the catchAll (400 otherwise); (2) UseAssignmentTable.ruleId must exactly equal the route row's own ruleId (400 if mismatched). Read: handoff-router-get/-list schedule rows now include assignmentTableRuleId and assignmentTableColumnKey. UseAssignmentTable assignments are representable. Resolve the assignment-table rule ID via rule-list
- 2026-11-10 (CEH-12557, edge PRs #2197+#2278): ConvertLead is REJECTED on Handoff router publish with 400 edge.router-action-unsupported (the Handoff backend no longer supports it). Do NOT include {type: 'ConvertLead'} in crmActions; existing routers with stored ConvertLead also fail to update until it is removed. The 2026-07-15 'ConvertLead is the only CRM action' and the 2026-07-30 caveat are superseded
- 2026-11-13 (CEH-12614, edge PR #2288): New `Owner` assignment type on `handoff-router-create` / `-update` — `{type: 'Owner'}` on a route row whose rule is an ownership rule. Constraints: (1) only valid on a route row, NOT the catchAll (400 otherwise); (2) the row's rule must be an ownership rule (400 on a non-ownership-rule row). Writes `ruleType: Ownership` with `UseRule{scheduleWithTeamMember: OwnerOnly, index: 0, required: true}`. Read: `Ownership` paths are representable; the routing summary shows `owner: true`. An owner path that allows any team member (`AllowWithAny`) reads as `owner: true` but stays non-representable, because Edge writes only owner-only. Resolve the rule type via `rule-list`
- 2026-11-13 (CEH-12640, edge PR #2291): Bug fix — a Handoff router built through Edge with routes but no `catchAll` now correctly reads back `representable: true` (previously incorrectly read `false`). No-catch-all representable routers now use full-replace semantics on update (not overlay).
- 2026-11-16 (CEH-12654, edge PR #2412): Bug fix — catchAll has three update cases on handoff-router-update — leave it out to keep it, pass null to delete it (previously null was incorrectly treated the same as leaving it out), or pass an object with the new catch-all. Removing the catch-all from a router that has no rows is rejected (400). On create: leave it out or pass null for no catch-all; pass an object to add one.
