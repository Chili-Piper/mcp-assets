# Concierge router API history

Dated notes on API changes behind this skill. Newer entries can supersede older ones. `api-reference.md` holds the current shapes.

- 2026-07-22: form/trigger writes must only REFERENCE existing data fields (standard defaults like PersonEmail always valid; custom fields by their UUID — an unknown dataField fails the write with 400 → references/api-reference.md § Data fields)
- 2026-07-31 (CEH-11177, edge PR #1030): data-field-list/get/create/update/delete are now available — the prior 'API gap' note is retired; use data-field-list to discover existing custom field references before a write
- 2026-08-04 (CEH-11197, edge PR #1037): DataFieldReference is a plain string on the wire (e.g. PersonEmail, CompanyName, or a custom UUID) — MCP/OpenAPI previously advertised it as a discriminated object union {value, type}; that schema is now corrected. data-field-delete returns 204 No Content
- 2026-07-15: three edge changes merged 2026-07-09 — DISTRO-4614 (#959) removed the routing 409 on update (app-built routers now edited via opaque-preserve overlay; the spec's operation description still shows the stale 409 text; the FORM 409 for third-party webforms noted here is superseded by the 2026-08-19 note below); DISTRO-4626 (#963) populates the derived slug on create/get/update responses (was always null) — capture the booking URL from the create response; DISTRO-4623 (#962) surfaces top-level inAppButton/routerLink read views and makes all three trigger kinds (form/inAppButton/routerLink) writable, each replacing only its own kind. No activate/deactivate and no status field — every write is live on success. Renaming re-derives the slug (public URL changes). Field truth → references/api-reference.md.
- 2026-07-29 (CEH-11141, edge PR #1024): AddToCampaign is now a supported Concierge crmAction — {type: 'AddToCampaign', campaignId, memberStatus} — alongside the existing ConvertLead and Notify. Updated in references/api-reference.md § Write shapes (crmActions grammar).
- 2026-07-30 (verified on a live tenant): ConvertLead written via the API is INVISIBLE in the Concierge Flow Builder — the API accepts and publishes it (node is real in the draft+published trees and fires post-booking), but the canvas renders no node and the SCHEDULED-branch ACTION menu offers no Convert Lead, so admins cannot see, edit, or remove it in the UI; inspect/remove only via concierge-router-get/-update. Whenever a write includes ConvertLead, call it out to the admin explicitly in the plan and the result. AddToCampaign UI rendering not yet verified
- 2026-08-03 (CEH-10905, edge PR #1031): concierge-list-routers and concierge-router-get now include formFields on each router — a list of ConciergeFormField objects (reference, label, requirement, fieldType with pick-list options, description, placeholder, order); always empty for third-party webform routers
- 2026-08-13 (CEH-11300/CEH-11302, edge PR #1069): Four Concierge write-model changes — (1) catchAll is now OPTIONAL on concierge-router-update: omitting it preserves the router's existing catch-all (still REQUIRED on create at that time). (2) New crmActions: SalesforceUpdateFields / HubspotUpdateFields (Update Record) and SalesforceUpsertRecord / HubspotUpsertRecord (Create/Upsert Record, Concierge only — not Handoff); field shapes in references/api-reference.md. (3) campaign-list and campaign-search are now available to look up Salesforce campaignIds for AddToCampaign actions
- 2026-08-13 (CEH-11303, edge PR #1072): SalesforceUpdateOwnership / HubspotUpdateOwnership added — {type: 'SalesforceUpdateOwnership', contact: [{object, field}], lead: [{field}]} and {type: 'HubspotUpdateOwnership', contact: [{object, field}]} — always assigns the CRM record owner to the booked host; also supported on Handoff
- 2026-08-13 (CEH-11313, edge PR #1073): EdgeUpdateFieldValue timeZone field widened from ZoneOffset to ZoneId — named timezones (e.g. America/New_York) are now valid in Update Record CRM action field values; RelativeQuarter subtype added (previously only RelativeDay/RelativeWeek/RelativeMonth)
- 2026-08-18 (CEH-11358, edge PR #1087): catchAll is now OPTIONAL on both create and update — omitting it produces a router with no fallback path (unmatched requests are not scheduled). The 'required on create' constraint is lifted
- 2026-08-19 (CEH-11363, edge PR #1088): thirdPartyForm trigger mapping is now writable on create and update — {thirdPartyForm: [{formFieldName, dataField, label?}]}, mutually exclusive with form. The RouterFormNotRepresentable 409 is retired — third-party webform routers no longer reject writes via this path. Writing thirdPartyForm on a Chili-webform router converts it to a third-party router, and vice versa. Per-field enrichment (waterfallId, automapped url) is preserved across updates but not exposed or settable via the API.
- 2026-09-03 (CEH-11590/CEH-11591, edge PR #1151): Two changes. (1) SalesforceCreateEvent and HubspotCreateEngagement added as new Concierge crmActions (Create Event — post-booking calendar event in CRM). Settings: relatedTo (REQUIRED on write; Concierge supports the full relation set unlike Handoff; CEH-12077, edge PR #1890, 2026-11-04 made it required), meetingCancellationBehavior (default DoNothing), guestsBehavior (default DoNothing), owner (default Assignee). Full field shapes in references/api-reference.md. (2) concierge-router-get and concierge-list-routers now return the COMPLETE crmActions chain — previously unmodellable nodes collapsed the whole array to null; now they become an Other{kind} read-only placeholder and the walk continues so representable siblings are preserved. Other is read-only and REJECTED on write; representable becomes false when any placeholder was emitted
- 2026-09-04 (CEH-11538, edge PR #1148): pre-routing steps are now readable AND authorable — routingSteps is a top-level sibling of routing on read (get/list) and an optional field on create/update. Step union: {type: 'Enrichment', waterfalls: [{dataField, waterfallId}], timeoutSeconds?} (waterfalls non-empty; timeoutSeconds whole seconds), {type: 'SpamCheck', writeSpamScoreToDataField} (no spam-path outcome by design — superseded by CEH-11610 note below), {type: 'Unrepresentable', kind} (read-only marker). Update semantics: omit routingSteps to preserve, supply to FULL-REPLACE the steps dimension ([] clears). A router whose steps contain Unrepresentable reads representable=false, and an update SUPPLYING routingSteps on it is rejected 409 RouterRoutingNotRepresentable (a rows-only routing edit still works and preserves steps verbatim) — the 'routing 409 retired since DISTRO-4614' claim is now qualified by this one case. waterfallId is an opaque string — resolve via the new enrichment-waterfall-list tool (CEH-11541, edge PR #1155): {workspaceId*, pagination?} → {results: [{id, name, isCustom, isTemplate, fields, tiedToDataField?, exclusivelyFor?, metadata}], total, page, pageSize}; never invent it, a stale id only surfaces at publish time
- 2026-09-04 (CEH-11599, edge PR #1154): the ContactOptions read outcome now exposes its meeting/callSuccess/callMissed CRM-action chains (each an ordered list of the same crmAction union incl. Other; null = branch absent, [] = present with no actions) — still read-only/unwritable, representable stays false
- 2026-09-04 (CEH-11610, edge PR #1158): SpamCheck pre-routing steps now require an onSpam spam-path outcome on write — the '(no spam-path outcome by design)' clause from CEH-11538 is superseded. Add onSpam: EdgeRouteOutcome to the SpamCheck step on write: {type: 'Schedule', assignment, meetingTypeId} or {type: 'Redirect', url}; omitting onSpam returns 400. Schema models onSpam as Option[EdgeRouteOutcome] (additive/non-breaking) but the write conversion enforces presence. A backend SpamCheck with no spam-path yes reads as Unrepresentable
- 2026-09-08 (DISTRO-4632): progressive disclosure is now the default for known AI clients (Claude Code, Claude Desktop, Cursor, Windsurf, Cline, Continue) — tools/list returns each tool with a stub description and no input schema. concierge-router-create is particularly affected: its schema is ~78 KB (~26 k tokens) and an agent may report it as absent or unusable when the schema has not been loaded. Before calling concierge-router-create in an MCP session, first call describe-tools(names: ["concierge-router-create"]) to fetch the full input schema on demand. To revert to the legacy full-schema listing, pass X-MCP-Tool-Schemas: full as a request header (~26 k token cost per tools/list call)
- 2026-10-15 (CEH-11248/CEH-11809, edge PR #1372): concierge-router-update `routing` field changed from `EdgeRouterRouting` to `EdgeRouterRoutingUpdate` — updates are now always a **patch overlay** regardless of `routing.representable`. Rows matched by `ruleId`; within each `Schedule` row, fields are individually optional (omit to keep existing value, e.g. omit `timeout` to leave it unchanged); rows not listed are preserved; `catchAll` optional (omit to preserve). `representable` is now advisory: updates accepted for all routers. A new row (new `ruleId`) still needs `assignment` + `meetingTypeId`. Read model: `EdgeRoutingOutcome.Schedule` now surfaces `timeout` and `additionalAssignments` (additional app-built assignees; Edge-unmodelable kinds omitted)
- 2026-10-16 (CEH-11928, edge PR #1592): Schedule outcome now supports optional redirectAfterBooking {url, forwardFormDataAsQueryParams?, delaySeconds?} — routers with a post-booking redirect (previously representable=false) are now representable and editable; on patch, omit to keep the existing redirect; CRM actions and redirect are replaced separately (a CRM-only edit preserves an app-built redirect); on read, redirectAfterBooking appears in routing.rows[].outcome
- 2026-10-16 (CEH-11813, edge PR #1373): ContactOptions outcome is now patchable via concierge-router-update: {type: 'ContactOptions', timeoutMinutes?, meetingTimeout?, callMissedTimeout?} — patches only timeouts on an existing call-flow path (400 on non-call-flow path, new row, or absent branch); new read fields timeoutMinutes (options-page wait), meetingTimeout, callMissedTimeout on the ContactOptions read outcome. Schedule.timeout.onTimeout is now optional (null when the redirect has settings Edge cannot express; minutes still show); Schedule.timeout patch shape is now {minutes?, onTimeout?} — each field omitted means keep-existing (a minutes-only edit preserves a custom redirect)
- 2026-10-20 (CEH-12122, edge PR #1921): concierge-router-create and concierge-router-update now reject non-http(s), non-scheme-less redirect URLs with 400. Applies to: Redirect outcome url, Schedule redirectAfterBooking.url, and timeout.onTimeout redirect url. http/https and scheme-less (e.g. example.com) are accepted; javascript:, data:, and other custom schemes are not. Add a ⚠️ note in any plan that writes a redirect URL confirming the scheme is valid.
- 2026-11-03 (CEH-12121, edge PR #1920): `concierge-router-update` `redirectAfterBooking` has three update cases — leave the field out to keep the current post-booking redirect, pass `null` to delete it from the Schedule path, or pass an object with the new redirect. The 'on patch, omit to keep the existing redirect' clause from 2026-10-16 (CEH-11928) is superseded: `null` is now the explicit removal signal
- 2026-11-05 (CEH-12103, edge PR #1911): Schedule path's `additionalAssignments` is now writable on `concierge-router-update` — same shape as `assignment` (each item `{type: User, userId}` or `{type: Distribution, distributionId}`); omitted leaves the existing list unchanged; supplied replaces the assignees after the first with exactly this list (`[]` leaves only the primary assignee, removing all extras). Previously `additionalAssignments` was read-only on Schedule outcomes (CEH-11248, 2026-10-15); it can now be set and edited via the API. Use this to add, reorder, or remove extra assignees on a Schedule path that has more than one rep
- 2026-11-10 (CEH-12557, edge PRs #2197+#2278): ConvertLead is REJECTED on Concierge router publish with 400 edge.router-action-unsupported (the Concierge backend no longer supports it). Do NOT include {type: 'ConvertLead'} in crmActions; existing routers with stored ConvertLead also fail to update until it is removed (even a resend unchanged triggers the rejection). The 2026-07-30 note ('API accepts and publishes it') is superseded. Use a Distro router's convertLead field instead
- 2026-11-13 (CEH-12645, edge PR #2294): Correction — `concierge-router-create` `catchAll` is **required** at the backend (rejected with 'In catch-all: missing' when absent). The 2026-08-18 (CEH-11358) note stating catchAll was optional on create was incorrect documentation; the backend requirement was always present. `catchAll` remains optional on `concierge-router-update` (omit to preserve the existing catch-all)
- 2026-11-20 (edge PR #2436): `waterfallId` is now exposed on Chili webform field mappings in the read view — `EdgeProcessedChiliFormMapping` (the processed form trigger's `mapping` array in `concierge-list-routers` and `concierge-router-get` responses) now includes a `waterfallId` field on each field that has an enrichment waterfall attached. It is **read-only** and **not settable** via the form write; it is preserved from the existing config on update. The 2026-08-19 (CEH-11363) note's claim that waterfallId was 'not exposed' applied specifically to the `thirdPartyForm` mapping context (which still holds — thirdPartyForm per-field enrichment remains not exposed); Chili webform field mappings now expose `waterfallId` in the read view.
